# 视觉接触规划：统一入口

## 当前实现

`tools/vision/contact_moveit.py` 是实时视觉接触的唯一运动入口。默认仅规划，添加 `--execute` 才发送运动。
原固定姿态示范程序仍保留，用于复现已记录关节姿态；它不执行视觉接触。

规划步骤：

1. 检查机械臂控制器和关节状态广播器，读取新鲜球坐标和反馈。
2. 从运行中的 MoveIt 模型读取真实关节上下限。使用 `contact_arm` 的 KDL 位置逆解，多初值搜索球面目标。
3. 按接近方向筛选姿态：TCP 的近似前向轴与起点到目标方向夹角不超过 45°。
4. 沿退让直线每 2 mm 求一次位置逆解，采用这些可达姿态作为笛卡尔路点，从接触姿态反向计算默认 3 cm 的退让段。避免向五关节位置逆解强加不可行的完整固定朝向。必须完整完成，逐点验证偏离直线不超过 2 mm、姿态漂移不超过 10°、前向轴保持在接近方向的 45°以内。
5. 将退让段做时间反转，作为最终接近段；反转速度符号，保留加速度。
6. MoveIt 规划当前姿态到接近段起点的自由空间路径。两个段在停止状态拼接，检查接点连续性、关节限位、严格递增时间和最终位置误差。
7. 执行前重新检查控制器、新帧目标与关节反馈。失败不自动重复执行，超时请求取消。

目标默认是可见球面上的测量点。不会在求解失败时自动改成更远目标。两段路径只在全部验证后执行，不先执行自由空间段再尝试未知的接触段。

## 模型与场景约定

- `contact_tcp_approx` 位于 004 局部 Z 轴上，取现有几何模型的两指尖中点：`[0, 0, 0.110]` m。2026-11-18 用户明确确认该轴向总长为 110 mm；004 转动不再改变此中心点的位置。
- 原 `arm` 组仍以 `tool0` 为末端；仅新增的 `contact_arm` 使用位置逆解。
- `--approach-axis X Y Z` 可指定 TCP 坐标系中的实际前向轴。默认使用模型夹爪的局部 +Z 方向，报告中明确标注；与实物安装方向仍需核对。
- 节点向共享 MoveIt 场景添加/更新 ID 为 `contact_workspace_table` 的 2 m × 2 m × 5 cm 桌面盒。顶面默认为 base_link 的 z=0（沿用 URDF 对桌面的假设），留 0.1 mm 数值缝隙。可用 `--table-z` 改为实测高度。其他场景对象不会被删除；该桌面保留到场景重置或被显式移除。
- 速度和加速度缩放仍为 0.1。没有提高硬件速度或修改串口故障处理。
- 仍未建立目标球体的碰撞模型/允许接触对，没有自动闭爪、抬起或接触传感器。位置规划成功不能代表实际碰到球。

## 使用

新版模型需要先编译并重启 MoveIt。相机识别、相机 TF 和 ball_to_base 保持运行；新节点不依赖旧的 fingertip_approx 静态 TF，直接使用模型 FK。

```bash
source /opt/ros/jazzy/setup.bash
source /home/kiloming/ROS2-Based-6-DOF-Robotic-Arm/arm_ws/install/setup.bash

# 零间距球面目标，末段直线接近 3 cm，仅规划
python3 /home/kiloming/ROS2-Based-6-DOF-Robotic-Arm/tools/vision/contact_moveit.py

# 重新取样、规划完整路径并执行一次
python3 /home/kiloming/ROS2-Based-6-DOF-Robotic-Arm/tools/vision/contact_moveit.py --execute
```

参数：`--standoff 0.05` 指定在球面前 5 cm 结束；`--approach-distance 0.03` 指定末段直线长度；`--attempts 20` 指定逆解初值数量。每次运行独立重新规划，不复用上次轨迹。

默认报告 `/tmp/contact_moveit_report.json`，可用 `--report PATH` 指定路径，记录输入时间、关节限位、近似轴来源、桌面高度、IK 返回码、朝向筛选数、每个笛卡尔段的完成比例和拒绝原因，以及成功时的轨迹。

## 2026-11-18 更新与实物实验

- 固定 004 号 `wrist_rotation_joint` 为每次规划开始的反馈角度：逆解、笛卡尔段、自由空间规划均施加关节约束，执行前逐点检查。数值容差为 0.0001 rad（约 0.006°）。报告增加 `locked_wrist_rad`。这可能减少可达目标，不会在失败时自动释放该关节。
- 005 号是夹爪开合，不在本节点的五关节轨迹中。固定姿态示范程序是独立入口，不受本节点的 004 固定约束影响。
- 修复反转轨迹端点微小速度残差导致控制器拒绝执行：仅将不超过 1e-5 rad/s（另加 1e-12 浮点比较余量）的端点速度归零；显著速度或非有限值仍报错，中间速度和加速度保持原时间反转规则。
- 固定 004 号之前，实物曾接受 486 点轨迹，约 41 秒后因肘关节跟踪误差 82 超过原始值阈值 80 中断。重新规划的 691 点轨迹约 66 秒后因 `Feedback outside historical raw range` 中断，旧日志没有记录越界舵机编号或数值，不能归因于 004 或 005。
- 上述实验没有完成实物接触确认。固定 004 的版本已通过回归测试，尚未完成现场执行验证。不要把此前模拟成功视为固定关节版本的成功验证。
- 本次共 14 项单元测试通过，新增端点速度数值边界、固定关节约束及逐点检查测试。

其他同期改动：保留示范程序的 `--center-camera` 局部相机居中功能；夹爪控制器默认目标位置容差配置改为 0，取消该默认位置误差检查，硬件范围和跟踪故障检查仍保留。清理旧入口 `approach_ball.py`、`approach_once.py`、`approach_target.py`、`contact_nudge.py`，实时视觉靠近统一使用本文入口。

## 轴线上中心点修正（第一轮占位尺寸验证，已被下述实测更新替代）

旧的 `fingertip_approx.json` 来自单姿态下“相机向前 110 mm、向下 30 mm”的估算，横向偏离 004 轴约 73.6 mm；不能把它当作夹爪中心。旧文件仅作为历史采集参考保留，当前 contact_moveit 不读取它。

现将接触参考改为两指尖前端平面的中点，并与 URDF 中的夹指长度保持一致。它不是球心，也不是单个夹指表面。保持现有夹爪碰撞几何，未用相机到夹爪的 110 mm 冒充腕轴到夹爪长度。需要测量 004 安装基准到指尖平面的轴向距离后再校正实物尺寸。

程序会拒绝仍加载旧侧向 TCP 的 MoveIt 实例，并提示重新编译/重启。004 固定约束和轨迹逐点检查继续保留。中心点对 004 旋转不变的回归测试通过，不代表原始关节零位、轴线或相机外参已标定准确。

修正后的隔离规划验证（ROS_DOMAIN_ID=88、mock 硬件、real_joint_limits）：合成目标 [0.25, 0, 0.15] m，找到 3 个逆解候选，生成 339 点完整轨迹，末段完成率 100%，终点模型误差 0.0017 mm；004 最大角度变化 9.1516287e-05 rad。此次仅规划，未发送实物或模拟运动。普通 demo 的更大加速度配置曾触发现有端点速度阈值；没有修改该阈值，此结果仅适用于上述 real_joint_limits 配置。

## 实测 110 mm 更新（当前版本）

用户进一步确认：004 输出安装基准到两指尖前端中点，沿夹爪轴向距离为 110 mm。TCP 使用 `[0, 0, 0.110]` m；该数值不是从相机距离推导。

原 60 mm 不再叠加为前向安装间距。夹爪安装平面与 tool0 移至 004 输出基准，保留近似掌部 35 mm、夹指 75 mm，使可视和碰撞几何的前端与 TCP 一致。近似腕部外壳放在输出平面后方，避免再次算入前向长度。总长已确认，但内部尺寸、外壳形状和各关节轴线仍需核对。

运行程序检查加载的 TCP 是否为轴线上 110 mm；旧的侧偏或 170 mm MoveIt 实例必须重启。004 固定约束继续生效。历史 170 mm 模型的规划结果不能代替本次几何验证。

110 mm 模型隔离验证：mock 驱动、ROS_DOMAIN_ID=88、real_joint_limits，合成目标 [0.25, 0, 0.15] m，8 个候选、327 点轨迹、末段完成率 100%，004 最大变化 1.4020773e-06 rad。仅规划，无实物运动。14 项单元测试及两个模型/配置包编译通过。
