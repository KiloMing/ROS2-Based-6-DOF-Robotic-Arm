## 配置链路

1. `arm_ws/src/arm_description/urdf/arm.urdf.xacro` 展开得到 robot_description；五个 revolute 依次是 base、shoulder、elbow、wrist_pitch、wrist_rotation。右夹指 mimic 左夹指，只向主动左夹指下命令。
2. `display.launch.py` 使用 GUI joint state publisher 提供关节状态，robot_state_publisher 结合 URDF 计算 `/tf` 与 `/tf_static`，RViz 显示几何。这一入口不证明控制器执行成功。
3. `control.launch.py` 读取 description/config/controllers.yaml，启动 controller_manager、joint_state_broadcaster 和两个轨迹控制器。GenericSystem 提供模拟状态；控制反馈经 `/joint_states` 回到 TF/RViz。不要同时运行 GUI 和控制反馈发布相互竞争的关节状态。
4. MoveIt `.setup_assistant` 指向上述 Xacro 和 `config/my_robot_arm.srdf`。SRDF 的 arm 链为 base_link → tool0，gripper 定义夹指组，另有命名姿态、末端与 world 固定虚拟关节。
5. `joint_limits.yaml` 补充速度/加速度，`kinematics.yaml` 配置运动学；MoveIt 生成路径并时间参数化。`moveit_controllers.yaml` 映射 FollowJointTrajectory action 到两个控制器；`ros2_controllers.yaml` 定义实际关节和接口。两者职责不同，名称、关节集合、action namespace 必须对应。
6. 执行链：move_group → FollowJointTrajectory → JointTrajectoryController → GenericSystem → JointStateBroadcaster → TF → RViz。Plan 成功不自动证明 Execute 成功。

## 错误清单：症状、根因、处理与当前状态

| 问题 | 症状与根因区别 | 处理及本次核查 |
|---|---|---|
| collision 嵌套 | 将 collision 放进 visual 属于模型结构错误；XML 能解析不代表 URDF 碰撞结构有效，可能出现碰撞几何缺失或模型加载异常 | collision 应为 link 的直接子元素，与 visual 并列；当前无 visual/collision 嵌套，Xacro 展开通过 |
| rviz 安装目录缺失 | colcon/CMake 安装阶段找不到源目录，与 RViz 运行时插件故障不同 | 当前 CMakeLists.txt 仍安装 rviz、meshes，而 Git 中这两个目录均不存在；干净克隆可复现性仍有缺口。应按实际资源补齐目录或移除无用安装项，本轮保留代码并记录 |
| joint_limits 浮点类型 | YAML 中 1 与 1.0 类型不同；MoveIt 参数期望 double 而获得 integer 时可能在节点启动/参数加载时失败 | 当前 max_velocity/max_acceleration 均为浮点，解析和类型检查通过；不是 SRDF 语法修复 |

| ros2_controllers 空列表 | joints、command_interfaces、state_interfaces 为空会导致控制器配置/激活或接口申请失败，Execute 无可用控制器 | 当前 arm 五关节、gripper 左夹指，position 命令和 position/velocity 状态列表非空；与 MoveIt 关节列表一致 |
| 双 install 混用 | 修改源码后实际启动旧配置，错误反复；源文件正确不证明运行参数正确 | 当前环境无法确认历史加载路径。新终端先 source Jazzy，再只 source 目标 arm_ws/install/local_setup.bash；用 ros2 pkg prefix 与 AMENT_PREFIX_PATH 核实实际路径。不要未经检查删除其他 install |
