# M1.1 机械臂真实硬件接入基线（2026-11-13）

> 状态：资料核对与离线准备；**没有执行本轮实物读写和 ros2_control 运行验收**。此文所列历史值不是本轮确认的电气/机械安全限位。

## 1. 目标与当前边界

目标：在不破坏已完成的 MoveIt 2 / GenericSystem 虚拟控制链的前提下，核实真实舵机的通信、状态反馈、关节映射，为单独的 `arm_hardware` / `hardware_interface::SystemInterface` 设计输入。

当前 Git 仓库有 `arm_description` 与 `arm_moveit_config` 两个功能包；缺少真实硬件插件。五个旋转关节 `base_joint / shoulder_joint / elbow_joint / wrist_pitch_joint / wrist_rotation_joint` 与一个主动夹指 `left_finger_joint`；`right_finger_joint` 为 mimic，不能当第七个独立驱动轴。

历史已使用的硬件路径（**本轮需复核当前端口**）：

```text
Ubuntu / ROS 2 Jazzy
  └─ USB → CH340 (历史 VID:PID 1a86:7523、/dev/ttyUSB0)
      └─ YH-K32 控制板（STM32F103C8T6）
          └─ 总线舵机 ID 000..005 → 实体机械臂
```

YH-K32 的 USB 上位机指令与总线舵机自身查询指令是**两层接口**。舵机协议支持读位置，不代表原厂 YH-K32 固件一定将读取应答经 USB 返回 Linux 主机。**未证实反馈链路前，不将写入的期望角当作测得角。**

## 2. 协议原件摘要

来源：`docs/reference/2026-11-11/舵机指令表（通信协议）(2).docx`；另参见 `docs/reference/originals/YH-K32控制板使用手册.pdf`。以下只说明资料中的格式，是否在当前 USB→YH-K32 路径生效需要实验验证。

| 目的 | 示例 | 原件中描述的返回 | 本轮状态 |
|---|---|---|---|
| 查询舵机 ID | `#000PID!` | `#000P!`（个别固件还含 `#OK!`） | 待测 |
| 查询工作模式 | `#000PMOD!` | `#000PMOD1!` 等 | 待测 |
| 查询当前位置 | `#000PRAD!` | `#000P1500!` 等 | 待测 |
| 位置控制（**不要在首次探测发送**） | `#000P1500T1000!` | 无返回 | 不执行 |
| 停在当前位置 | `#000PDST!` | `#OK!` | 未验证其现场适用性 |

原件规定 ID 为三位数字；位置/时间为四位数字，位置示例在 0500–2500 之间、时间为 0000–9999 ms；模式 1–4 为角度舵机模式，5–8 为马达模式。原件称默认通信波特率为 115200，但**不能仅据文档假定当前控制板转发链路的参数与能力**。

**本阶段禁止**以自动探测名义发送更改 ID、模式、波特率、零点、机械端点、开机动作、恢复出厂的设置命令；禁止发送广播 ID 255；禁止直接松开承重关节的扭矩。

## 3. 既有模型及历史标定线索

精细数值见 `hardware/servo_calibration.csv` 与 `hardware/gripper_opening_points.csv`。

- ID 000→base：历史启动原始值 1600，后更正 **零位原始值为 1500**，raw 增大对应 ROS 正方向。
- ID 001→shoulder：启动 1900、零位 1500，raw 增大对应 ROS 负方向；记录中软件允许范围 700–2300。
- ID 002→elbow：启动 2100、零位 1500，raw 增大对应 ROS 正方向。
- ID 003→wrist_pitch：启动 800、零位 1500，raw 增大对应 ROS 负方向。
- ID 004→wrist_rotation：启动/零位 1500，raw 增大对应 ROS 正方向。
- ID 005→gripper：开口宽度随 raw 增大而减小；历史记录显示明显非线性，**采用分段插值而非统一角度比例**。
- Xacro 对五旋转关节使用了软件限位；这些数值目前不应替代实物机械限位测试。夹爪模型以总开口 0–60 mm 映射到主动左夹指 0–30 mm，右夹指由 mimic 产生。

## 4. 本轮优先执行的非运动诊断

接上控制板前核实当前供电和支撑状态；**串口打开可能导致某些控制板复位，已存储的开机动作也必须先排除**。不要让机械臂在无人支撑或可能碰撞的状态下通电。

1. 仅检查主机设备枚举，记录终端输出：
   ```bash
   lsusb
   ls -l /dev/serial/by-id/
   ls -l /dev/ttyUSB*
   ```
   设备节点可能不是 `/dev/ttyUSB0`，优先使用持久化 `/dev/serial/by-id/` 路径。
2. 确认当前 USB 设备确实是 YH-K32 所在 CH340，且不存在其他程序抢占串口。
3. 安装 `pyserial` 后，使用仓库 `tools/servo_query_probe.py` 发出**仅查询**的 ID/模式/位置命令，保存 TX/RX 原始日志：
   ```bash
   sudo apt install python3-serial
   python3 tools/servo_query_probe.py --port /dev/ttyUSB0 --ids 000 001 002 003 004 005
   ```
   如果 pyserial 已安装则无需重复安装；也可在独立虚拟环境使用 pip。根据实际枚举替换端口；首次可只测一个已确认 ID。
4. 通过 YH-K32 实际 RX 结果判断：`#000P1500!` 等有效值 / 仅回显查询指令 / 无应答 / 杂乱数据 / 其他板级反馈。**任何一次有数据不等于反馈真实**，需要改变舵机位置后读数相应变化的复核；运动测试另行制定安全步骤。
5. 如果无应答，先核对原厂固件是否具备 USB 读回/透传；不要以超时作为舵机没有位置传感能力的证据。
